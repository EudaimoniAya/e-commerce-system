# ADR-002：测试与数据库/Redis 策略

- **状态**：已采纳
- **日期**：2026-07-11（MySQL）；2026-07-27 增补 Redis（`infra-redis`）；2026-08-17 增补 PostgreSQL/pgvector（`infra-ai-pgvector`）；2026-08-24 增补决策 10 本地三库统一监督器（`infra-devbox-services`）
- **背景**：`infra-database` change 引入 MySQL、SQLAlchemy 2 异步栈、Alembic 与 integration 测试。`infra-redis` change 引入 Redis 8 单实例、async 客户端与 readiness 双依赖检查。`infra-ai-pgvector` change 引入 PostgreSQL（AI 读库 + pgvector）、独立 `AiBase`/`alembic_ai/` 入口、`Embedder` 抽象与 readiness 三依赖聚合。本地与 CI 的提供形式不同，需统一测试惯例，避免 SQLite 替身带来的方言差异与假阳性。

## 决策

### 1. 本地与 CI 的 MySQL 提供形式

| 维度 | 本地开发 | CI（GitHub Actions） |
|------|----------|----------------------|
| 提供方式 | **devbox services**（`mysql80@latest`） | **mysql service container** |
| 传输 | unix socket（`skip-networking`） | TCP `127.0.0.1:3306` |
| Socket 路径 | `/tmp/e-commerce-system-mysql.sock` | — |
| 数据持久化 | 项目内 `db-data/mysql/`（gitignore） | 每 job 全新实例 |
| 启动入口 | `task mysql:up` → `scripts/devbox/mysql_up.sh`（`db:up` 为三库总闸） | workflow `services.mysql` + health check |

**原则**：提供形式可以不同，但 **MySQL 大版本（8.0）、charset（utf8mb4）、pytest 用例** 必须一致；同一套 integration 测试在本地与 CI 均应通过。

**本地连接串示例**：

```text
mysql+asyncmy://root@localhost/ecommerce_dev?charset=utf8mb4&unix_socket=/tmp/e-commerce-system-mysql.sock
```

**CI 连接串示例**：

```text
mysql+asyncmy://root@127.0.0.1:3306/ecommerce_test?charset=utf8mb4
```

**不采用**：本地 docker-compose 提供 MySQL（本 change 以 devbox 与 bootstrap 工具链一致）。

### 2. 双库策略

同一 MySQL 实例内维护两个逻辑库：

| 库名 | 用途 | 本地 | CI |
|------|------|------|-----|
| `ecommerce_dev` | `task dev`、`task migrate` 默认目标 | ✓ | ✗ |
| `ecommerce_test` | pytest `@integration` | ✓ | ✓（唯一业务库） |

- 开发者在 `.env` 中默认指向 `ecommerce_dev`；跑 integration 测试时改为 `ecommerce_test`（见 `.env.example`）。
- CI **仅** 使用 `ecommerce_test`，不在 CI job 中操作 `ecommerce_dev`。
- `task dev` 依赖 `db:up` 自动启动三库；本地 `task ci` 亦经 deps `db:up` 就绪（lint + migrate + test 前置）；CI 由 workflow `services` 提供三库，`task test` 本身不声明 devbox deps。

### 3. Schema 真相来源：Alembic

- **唯一 SSOT**：`alembic upgrade head`；生产与测试路径均通过 migration 建表。
- **禁止** 以 `Base.metadata.create_all()` 作为生产或 CI 的 schema 初始化手段。
- 首条 migration 创建 infra 验证表 `_infra_migration_smoke`（非业务表），用于验证迁移管线与 integration CRUD。
- Alembic CLI 使用 **同步 engine** 执行 `upgrade`/`downgrade`；应用运行时保持 **async** `AsyncSession`（迁移频率低，可接受）。

### 4. 异步驱动：asyncmy

- 连接串格式：`mysql+asyncmy://`
- 栈：`create_async_engine` + `async_sessionmaker` + SQLAlchemy 2 `AsyncSession`
- 路由与 repository 层使用 `async def`，与 FastAPI 异步模型一致。

**不采用**：

| 备选 | 否决理由 |
|------|----------|
| SQLite（内存或文件） | 与生产 MySQL 方言/行为不一致，integration 假阳性风险 |
| 同步 PyMySQL + `def` 路由 | 与全 async 选型不符 |
| aiomysql | 社区与 SQLAlchemy 2 async 生态弱于 asyncmy |

**注意**：`AsyncSession` 默认 lazy load 在请求上下文外易踩坑；repository 层对跨请求数据应显式 `selectinload` / `joinedload`，或在单次查询内完成加载。

### 5. Integration 测试惯例

**Marker**：依赖 MySQL 与/或 Redis 的测试使用 `@pytest.mark.integration`，在 `pyproject.toml` 注册说明（MySQL 需 `task db:up`；Redis 需 `task redis:up`；`DATABASE_URL` 指向 `ecommerce_test`，`REDIS_URL` 使用逻辑库 `/1`）。

**SAVEPOINT 事务隔离**（每个 test）：

```text
connect → outer BEGIN → SAVEPOINT session (join_transaction_mode="create_savepoint")
→ dependency_overrides[get_db] → HTTP 共用同一 session
→ service 内 commit() 仅提交 SAVEPOINT
→ teardown: pop override → close session → outer ROLLBACK → dispose engine
```

- 测试通过 `integration_client` fixture 发 HTTP，`get_db` override 使服务端代码使用测
  试 session（而非独立连接池）。
- `db_session` fixture 创建外层事务 + SAVEPOINT session，service 内的 `session.commit()`
  仅提交 SAVEPOINT 而非外层事务。teardown 时外层 ROLLBACK 实现零数据残留。
- `tests/testkit/db/` 下的 helper 使用同一 session 做 DB 状态断言（如
  `get_product_stock`、`backdate_order_expires_at`）。
- **探针例外**（不使用 `integration_client` / SAVEPOINT override）：
  - `tests/catalog/test_admin_seed.py` — 独立 engine 查 alembic migration seed
  - `tests/ops/test_readiness.py` — readiness 自建连接 ping MySQL/Redis
  - `tests/user/test_user_summary.py` — 纯 service + rollback `db_session`，无 HTTP
- **Redis fixture**：`tests/conftest.py` 提供 `redis_url`、`redis_client`（经 `get_redis()`）；写 key 用例依赖 `flush_test_redis_db`（对当前逻辑库 `FLUSHDB`，禁止 `FLUSHALL`）；integration 用例 autouse `reset_redis`（镜像 `reset_engine`）。
- **不** 采用每 test 删库、TRUNCATE 全表、sleep/wait 等更重手段。

**测试环境**：`APP_ENV_FILE=.env.test` 使 `get_settings()` 从 `.env.test` 加载配置；
`task test` 与 CI 通过 `Taskfile.yml` 注入该变量。

**用例分层**：

| 测试 | marker | 说明 |
|------|--------|------|
| `test_health_*` | 无 | liveness，不依赖 DB/Redis |
| `test_readiness_*` | integration | MySQL + Redis + PostgreSQL 均 ok → 200；任一 unavailable → 503 |
| `test_database_*` | integration | `SELECT 1` 等 MySQL 连接烟雾 |
| `test_redis_*` | integration | Redis PING、SET/GET/TTL |
| `test_migration_smoke_*` | integration | Alembic + `_infra_migration_smoke` CRUD |
| `test_pg_*` | integration | AI 库 `SELECT 1`、向量 insert + pgvector 相似度检索 smoke |
| `test_embedder_*` | integration | MockEmbedder 维度、配置不一致 fail-fast |
| `test_ai_migration_smoke_*` | integration | AI 库 Alembic + vector 扩展 + `_infra_ai_migration_smoke` CRUD |

**CI 顺序**：mysql + redis + postgres service 就绪 → `CREATE DATABASE ecommerce_test`（如需要）→ `alembic upgrade head` → `alembic -c alembic_ai.ini upgrade head` → 设置 `DATABASE_URL`、`REDIS_URL`、`AI_DATABASE_URL` 与 `EMBEDDING_*` → `task ci`。

**本地**：先 `task db:up`（三库总闸）；测试经 `APP_ENV_FILE=.env.test` 加载（`DATABASE_URL` → test 库，`REDIS_URL` → `/1`，`AI_DATABASE_URL` → `ecommerce_ai_test`，`EMBEDDING_*` 须显式配置）。本地 `.env.test` 为 gitignored，须与 `.env.example` AI 小节保持同步；CI 由 workflow env 覆盖。

> **TODO（`infra-devbox-services` 后续）**：fresh `db-data/` 后，test 库迁移依赖迁移冒烟测（`test_admin_seed` / `test_ai_migration_smoke`）的字母序，集成测试可能先跑而找不到表。已定方案：`tests/conftest.py` 增加 session 级 autouse 迁移 fixture，暂未实施。详见 [踩坑记录](../troubleshooting/db-data重建后task-ci失败-test库未迁移.md)。

**不采用 `scripts/*_curl_smoke.sh`**：业务 API 主流程与回归仅由 pytest integration（`tests/` + `task ci`）承担；README 可保留零散 curl 示例供手动调试，但不在 `scripts/` 维护与 integration 重复的 bash HTTP 编排（见 `test-architecture` spec）。

### 6. Taskfile 与数据库命令

| 命令 | 说明 |
|------|------|
| `db:up` / `db:down` / `db:reset` | 三库总闸（mysql + redis + postgresql，同一只 process-compose；须在 devbox shell 内） |
| `mysql:up` / `mysql:down` / `mysql:reset` | devbox MySQL 8 运维 |
| `redis:up` / `redis:down` / `redis:reset` | devbox Redis 8 运维 |
| `pg:up` / `pg:down` / `pg:reset` | devbox PostgreSQL 16 + pgvector 运维 |
| `migrate` | `alembic upgrade head`（deps `mysql:up`，默认 dev 库） |
| `migrate:ai` | AI 库 `alembic -c alembic_ai.ini upgrade head`（deps `pg:up`） |
| `migrate:all` | MySQL + AI 顺序 migrate |
| `migrate:new` | 新建 revision |
| `dev` | deps `db:up`（三库），再启动 uvicorn |
| `test` | pytest（含 integration，需 test 库、Redis 与 AI PG 可用） |
| `ci` | deps `db:up`（三库）；format + ruff + `migrate:all` + pytest |

### 7. 本地与 CI 的 Redis 提供形式

| 维度 | 本地开发 | CI（GitHub Actions） |
|------|----------|----------------------|
| 提供方式 | **devbox services**（`redis@8.0.x`） | **redis service container** |
| 传输 | TCP `127.0.0.1:6379` | TCP `127.0.0.1:6379` |
| 数据持久化 | 项目内 `db-data/redis/`（gitignore） | 每 job 全新实例 |
| 启动入口 | `task redis:up` → `scripts/devbox/redis_up.sh` | workflow `services.redis` + healthcheck |

**原则**：提供形式可以不同，但 **Redis 大版本（8.0 系列）与 pytest 用例** 必须一致；同一套 integration 测试在本地与 CI 均应通过。

**本地连接串示例**：

```text
redis://127.0.0.1:6379/0
```

**CI / 测试连接串示例**：

```text
redis://127.0.0.1:6379/1
```

**不采用**：本地 docker-compose 提供 Redis；PR CI 中 Redis 主从/哨兵/Cluster（Layer B HA 测试留给 staging）。

### 8. Redis 逻辑库隔离

同一 Redis 实例内用逻辑库编号区分 dev 与 test：

| 逻辑库 | 用途 | 本地 | CI |
|--------|------|------|-----|
| `db 0` | `task dev`、手动实验 | ✓（`.env`） | ✗ |
| `db 1` | pytest `@integration` | ✓（`.env.test`） | ✓ |

- `REDIS_URL` 为 **必填** Settings 字段；业务域 **仅** 通过 `app/infra/redis.py` 的 `get_redis()` 访问，禁止自行 `Redis.from_url`。
- 测试清理使用 `FLUSHDB`（当前库），**禁止** `FLUSHALL`。

### 9. 本地与 CI 的 PostgreSQL（AI 读库 + pgvector）

| 维度 | 本地开发 | CI（GitHub Actions） |
|------|----------|----------------------|
| 提供方式 | **devbox services**（`postgresql_16` + `postgresql16Packages.pgvector`） | **postgres service container**（`pgvector/pgvector:pg16`） |
| 传输 | TCP `127.0.0.1:5433`（devbox 默认，避免与系统 5432 冲突） | TCP `127.0.0.1:5432` |
| 数据持久化 | 项目内 `db-data/postgres/`（gitignore） | 每 job 全新实例 |
| 启动入口 | `task pg:up` → `scripts/devbox/pg_up.sh` | workflow `services.postgres` + `pg_isready` healthcheck |

**双库约定**（同一 PostgreSQL 实例）：

| 库名 | 用途 |
|------|------|
| `ecommerce_ai_dev` | `task dev`、本地 `.env` |
| `ecommerce_ai_test` | pytest `@integration` 与 CI |

**本地连接串示例**：

```text
postgresql+asyncpg://postgres:postgres@127.0.0.1:5433/ecommerce_ai_dev
postgresql+asyncpg://postgres:postgres@127.0.0.1:5433/ecommerce_ai_test
```

**Embedding 配置**：`EMBEDDING_PROVIDER`、`EMBEDDING_MODEL`、`EMBEDDING_DIMENSION`（**必填、无 Settings default**）；`.env.example` 与 CI 示例 `1024`。

**本地 `.env.test`**：须同步 `AI_DATABASE_URL` 与 `EMBEDDING_*`（gitignored；CI 由 workflow env 覆盖）。

### 10. 本地三库统一监督器与竞态纪律（infra-devbox-services）

**背景**：MySQL/Redis 原由 process-compose 监督，PostgreSQL 曾走 `pg_ctl` 旁路；数据目录三处（`mysql-data/`、`postgres-data/`、`.devbox/virtenv/redis/`）；`task ci` / `task dev` 曾并行 deps 多个 `*:up`，抢**同一只** process-compose 导致 `already running`。

**选择**：

- **一只监督器**：本地 MySQL/Redis/PostgreSQL 由**同一只 process-compose** 监督。冷启动一次 `devbox services up mysql redis postgresql -b` 点齐三名；监督器已运行则**跳过**（`up <单名>` 不能追加到已存在的监督器）。
- **`up` vs `start`**：`up <名>` 用于冷启动/注册；监督器已在跑时，分库启用用 `devbox services start <名>`（启用已注册的 Disabled 进程），**禁止**再对单名执行 `up`。
- **总闸语义**：`db:up` / `db:down` / `db:reset` = 三库（reset = down + 清空整个 `db-data/` + up）。`ci` / `dev` / `test:reports` / `ai:reindex-*` 只 deps **`db:up`**，禁止并行 deps 多个 `*:up`。
- **分库 down 必须带名**：`devbox services stop <mysql|redis|postgresql>`；**禁止**无名字 `devbox services stop`（会拆掉整只监督器，殃及其它库）。
- **PG 由插件服务托管**：`pg:up` = `initdb`（无 `PG_VERSION` 时）→ `start postgresql` → `pg_isready -h 127.0.0.1 -p 5433` → 建 AI 双库 + vector；不再 `pg_ctl start`。`PGHOST` 为 unix socket **目录**（`db-data/postgres/run`），应用仍连 TCP `127.0.0.1:5433`。
- **数据统一根 `db-data/`**：`mysql/`、`redis/`、`postgres/{data,run}`；旧 `mysql-data/`、`postgres-data/`、`.devbox/virtenv/redis/` 可手删，**不**提供自动迁移。
- 共享脚本 `scripts/devbox/services.sh`（监督器编排）+ `scripts/devbox/db_{up,down,reset}.sh`（总闸）+ `{mysql,redis,pg}_{up,down,reset}.sh`（分库）。

**旁注**：本 change（`infra-devbox-services`，2026-08-24）。

## 理由摘要

1. **真实环境测试**：MySQL 8 + utf8mb4 与生产一致，避免 SQLite 替身掩盖 JSON、约束、事务语义差异。
2. **双库隔离**：开发迁移与手动实验不污染测试库；CI 单库简化 workflow。
3. **Rollback 轻量**：同库多 test 快速、无删库成本，适合个人项目 TDD 节奏。
4. **形式分离、用例统一**：devbox 适配 WSL 本地体验，CI service container 适配 runner 无状态 job，pytest 用例一套维护。

## 不做什么

- 不用 SQLite 作为单元或 integration 替身
- 不在 CI 使用 `ecommerce_dev`
- 不用 `create_all()` 替代 Alembic 作为 schema SSOT
- 不在本 change 引入业务表或 docker-compose 本地 MySQL
- 不在 PR CI 验证 Redis HA 拓扑（主从/哨兵/Cluster）

## 影响

- 新增/修改代码须通过 `DATABASE_URL` / `REDIS_URL` 注入连接，禁止硬编码主机与库名
- integration 测试必须带 marker，并依赖 rollback / Redis flush fixture
- CI workflow 须在 pytest 前执行 `alembic upgrade head`，并声明 `services.redis`
- 跨域数据访问纪律见 [单体多域架构](./ADR-001-单体多域架构.md) 与 `.cursor/rules/cross-domain-imports.mdc`
